# VRGDG Feature Comparison

## Purpose and evidence boundary

This comparison evaluates the dedicated music-video workflow in VRGDG against the current Vesper Music Video Builder. It covers project and source handling, scene and storyboard planning, prompt interaction, enhancement and look work, and full-song assembly.

The VRGDG findings come from the local source checkout at `D:\User Folders\Documents\Projects\comfyui-vrgamedevgirl`. Its `__init__.py` declares version `v9.1.1` and update date `2026-08-06`. The source snapshot supplies the primary evidence. The upstream documentation links appear in [Sources](#sources).

The tables separate three kinds of statements:

- **Source-verified behavior:** the `How it works` column names source files, routes, persisted artifacts, or UI behavior found in the checkout.
- **Current Builder behavior:** the `Existing Builder equivalent` column describes the current project contract and code paths.
- **Product judgment:** the `Potential value` and `Recommendation` columns describe what fits the Builder's existing direction.

This comparison excludes LTX-specific tools and branches, generic workflow runners, model management, training, unrelated AI utilities, and general-purpose video-editor functions. It does not recommend replacing Resolve. The Builder remains a focused MiniMax H3 production system with a manual ChatGPT creative relay, artist/editor-provided SRT timing, machine-owned prompt structure, and separate Final Scene and Production Scene artifacts.

## Product baseline

The current Builder spine remains:

```text
Song -> Scenes -> Storyboard -> Visual Planning -> MiniMax H3 Generation -> Review -> Final Production
```

The relevant current implementation lives in:

- `backend/projects.py`, `backend/source.py`, and `backend/scenes.py` for schema-v7 project storage, master audio, SRT, and contiguous scene construction.
- `backend/storyboard.py` for validated scene direction, camera and motion notes, continuity notes, and reference selectors.
- `backend/visuals.py` for `keyframe_i2v`, `reference2video`, accepted keyframes, ordered references, and readiness checks.
- `backend/prompt_service.py` for deterministic H3 prompt compilation, reference mapping, source fingerprints, manual relay validation, and the saved Final Prompt.
- `backend/workflows.py`, `backend/render.py`, and `backend/render_jobs.py` for manifest-driven H3 execution and durable jobs.
- `backend/render_finalize.py` and `backend/render_production.py` for authoritative scene audio, Final Scene validation, controlled production upscaling, and Production Scene promotion.

## Recommendation summary

### Adopt

- Portable, self-contained project packages with explicit artifact identities and safe path rebasing.
- Preview-before-apply for controlled finishing decisions.
- Song-level scene coverage and ordering preflight built on the existing contiguous timeline contract.

### Adapt

- Audio peaks, beat markers, and timing diagnostics as advisory data.
- Instrumental-gap and vocal-tail validation without changing the supplied SRT.
- Planning-only shot schedules and a structured continuity state.
- Candidate still history, captured-frame review, notes, and remake intent.
- Versioned style-bible, motion-note, vocal-status, prompt-draft, and look-profile records.
- A full-song review draft, assembly manifest, durable assembly jobs, and Resolve metadata export.

### Ignore

- Whisper or stable-ts transcription as a competing source of truth.
- VRGDG's local Gemma, LM Studio, API, and Browser AI runner architecture.
- Freeform prompt generation that can author timing, references, tags, or method structure.
- Filename-sorted concatenation and threshold-only coverage checks.
- Duplicating the Builder's existing authoritative-audio, Final Scene, Production Scene, and controlled-upscale contracts.
